1. Project Overview

TraceableHands is a trustless charity donation platform built on Ethereum. Donors contribute USDC stablecoins to a milestone. When the funding goal is reached, 50% is automatically released to the vendor. The vendor then uploads proof of delivery to IPFS. All donors who contributed can vote to Approve, request More Proof, or Reject the delivery. A majority decision automatically releases or refunds the remaining 50%. This is crowd auditing — no trusted third-party auditor is needed.

State machine:

Funding ──(goal reached)──▶ ProofPending ──(proof uploaded)──▶ VotingOpen
                                  ▲                                  │
                                  │       (needs more proof)         │
                                  └──────────────────────────────────┤
                                                                     ▼
                                              Completed ◀── majority Approve
                                              Failed    ◀── majority Reject / max rounds
                                                │
                                        (refunds available)

Install these before you start:

3. First-Time Setup & Running the App

Step 1 — Clone the repository

git clone https://github.com/YOUR_USERNAME/FT5004-Traceablehands.git
cd FT5004-Traceablehands

Step 2 — Install dependencies

# Root (Hardhat + contracts)
npm install

# Frontend (React)
cd frontend
npm install
cd ..

Step 3 — Create environment file

Create a file called .env in the project root (not inside frontend/):

SEPOLIA_RPC_URL=https://eth-sepolia.g.alchemy.com/v2/YOUR_ALCHEMY_KEY
PRIVATE_KEY=your_metamask_wallet_private_key_without_0x_prefix

ℹ️ To find your private key in MetaMask: Account Options → Account Details → Export Private Key. Use this account only for testing — never store real funds in it.

Step 4 — Compile smart contracts

npx hardhat compile

This generates ABI files in artifacts/. You'll see Compiled N Solidity files successfully.

Step 5 — Run tests (optional but recommended)

npx hardhat test

All tests should show green checkmarks.

Step 6 — Deploy to Sepolia

npx hardhat run scripts/deploy.js --network sepolia

This saves contract addresses to deployed-addresses.json in the project root.

Step 7 — Copy contract files to frontend

cp deployed-addresses.json frontend/src/contracts/
cp artifacts/contracts/TraceableHands.sol/TraceableHands.json frontend/src/contracts/
cp artifacts/contracts/MockUSDC.sol/MockUSDC.json frontend/src/contracts/

Step 8 — Start the frontend

cd frontend
npm start

Open http://localhost:3000 in your browser. MetaMask will auto-prompt to switch to Sepolia.

4. Workflow: After Making Code Changes

Scenario A — You only changed React frontend code (App.js, CSS, etc.)

1

Save your files.

2

If npm start is already running, the browser hot-reloads automatically — no extra steps needed.

3

If not running: cd frontend && npm start

4

Commit and push to GitHub (see Section 5).

✅ Frontend changes do not require redeployment of smart contracts.

Scenario B — You changed the smart contract (TraceableHands.sol or MockUSDC.sol)

Every contract change requires a full redeploy because the deployed bytecode on Sepolia cannot be edited.

1

Recompile

npx hardhat compile

Fix any compilation errors before continuing.

2

Run tests

npx hardhat test

Make sure all tests pass. If any fail, fix them before deploying.

3

Redeploy to Sepolia

npx hardhat run scripts/deploy.js --network sepolia

This creates fresh contract instances. The old deployed addresses are now obsolete — do not use them.

4

Copy updated files to frontend

cp deployed-addresses.json frontend/src/contracts/
cp artifacts/contracts/TraceableHands.sol/TraceableHands.json frontend/src/contracts/
cp artifacts/contracts/MockUSDC.sol/MockUSDC.json frontend/src/contracts/

This updates the contract ABI and addresses that the React app uses.

5

Restart the frontend

cd frontend
npm start

Hard refresh the browser (Cmd+Shift+R / Ctrl+Shift+R) to clear cached contract data.

6

Re-setup MetaMask

Since new contracts were deployed, you need to get test USDC again from the new MockUSDC contract. Click Get 1000 Test USDC in the app.

7

Commit everything to GitHub

Include deployed-addresses.json and the updated ABI JSON files in frontend/src/contracts/.

⚠️ Changing a deployed contract is not possible. Solidity contracts are immutable once deployed. Any logic change = new deployment = new address. Always update deployed-addresses.json after every deploy.

6. Testing Multiple Roles (Multiple Accounts)

MetaMask supports multiple accounts under one seed phrase. Each account has a different wallet address. You can switch between them to simulate every role in the system without needing multiple browsers.

How to create additional accounts

  1. Open MetaMask → click your account icon (top-right circle)
  2. Click Create Account
  3. Name it (e.g. "Donor", "Auditor", "Vendor")
  4. Repeat for each role you need

ℹ️ All accounts under the same MetaMask share the same seed phrase (recovery phrase) but have different private keys and addresses. They are independent wallets for all practical purposes.

Suggested test setup

AccountRole to testActions
Account 1CharityCreate milestones; can also submit proof
Account 2VendorPaste this address when creating milestone; submits IPFS proof; receives funds
Account 3Donor 1Get test USDC, donate, then vote when proof is submitted
Account 4Donor 2Get test USDC, donate, then vote (needed for quorum of 2+)
Account 5Donor 3Optional third voter for full majority testing

Each account needs a small amount of Sepolia ETH for gas. Get it free from sepoliafaucet.com.

Full end-to-end test flow

1

Account 1 (Charity): Create a milestone with Account 2 as the vendor address, goal 200 USDC, 30 days.

2

Account 3 (Donor 1): Get 1000 test USDC. Donate 100 USDC to the milestone.

3

Account 4 (Donor 2): Get 1000 test USDC. Donate 100 USDC. Goal is reached → 100 USDC auto-sent to Account 2 (vendor). Milestone moves to Proof Pending.

4

Account 2 (Vendor): Upload delivery photo to Pinata (see Section 7). Copy the CID. On the milestone card, paste the CID and click Submit Proof & Open Voting. Milestone moves to Voting Open.

5

Account 3 (Donor 1): Review the IPFS proof link. Click Approve.

6

Account 4 (Donor 2): Review the proof. Click Approve. Since both donors (the required quorum) approved, the remaining 100 USDC is automatically sent to Account 2. Milestone is Completed.

ℹ️ The minimum voters needed = min(3, total donors). With 2 donors in this example, both must vote. With 3+ donors, at least 3 must vote before a decision triggers.

7. IPFS — What It Is & How to Upload Evidence

What is IPFS?

IPFS (InterPlanetary File System) is a peer-to-peer storage network. Instead of storing files on a central server (which can go down or be censored), IPFS distributes files across thousands of nodes worldwide.

Every file uploaded to IPFS gets a CID (Content Identifier) — a cryptographic hash fingerprint derived from the file's contents. If the file changes by even one byte, the CID changes. This makes it tamper-proof: you can always verify the exact file an auditor referenced.

✅ Why TraceableHands uses IPFS: When a vendor submits proof of delivery, they upload photos/receipts to IPFS and store the CID on the Ethereum blockchain. This CID is permanent and publicly verifiable — anyone can retrieve the original evidence at any time, forever. No central server can delete it or swap the files. Donors can verify the proof before voting.

Example CID

QmXoypizjW3WknFiJnKLwHCnL72vedxjQkDDP1mXWo6uco

Access any IPFS file via: https://ipfs.io/ipfs/<CID>

How to upload evidence photos

Method 1: Pinata (Recommended — Free, No code needed)

  1. Go to pinata.cloud and create a free account
  2. Click Upload → File
  3. Select your photo, receipt, or any evidence file
  4. Click Upload
  5. The file appears in your dashboard with a CID (starts with Qm… or bafy…)
  6. Copy just the CID (not the full URL) and paste it into the audit form in the app

Method 2: web3.storage (Alternative — Free)

  1. Go to web3.storage and sign in with GitHub
  2. Click Upload Files and select your file
  3. Copy the CID from the dashboard after upload completes

Method 3: NFT.Storage (Alternative — Free)

  1. Go to nft.storage and create an account
  2. Click Upload and select your file
  3. Copy the resulting CID

Verifying your upload

After uploading, paste your CID into a browser:

https://ipfs.io/ipfs/YOUR_CID_HERE

It may take 1–2 minutes to propagate. Once the file loads, your CID is ready to use.

⚠️ Privacy warning: IPFS files are public by default. Only upload photos/documents that you are authorised to share publicly. Do not include personal data like full names, ID documents, or financial records unless they are meant to be public evidence.

8. Smart Contract Architecture

Contracts

ContractPurpose

Key functions

FunctionWho calls itWhat it does
createMilestone()CharityCreates a new funding goal on-chain
donate()DonorLocks USDC in escrow; triggers 50% release when goal is reached
submitProof()Vendor or CharityUploads IPFS CID on-chain; opens voting period for donors
crowdVote()DonorCasts Approve / NeedsMoreProof / Reject vote; auto-resolves on majority
claimRefund()DonorReturns donor's share if deadline passed or milestone was rejected

Crowd voting rules

RuleValue
Minimum voters before decisionmin(3, total donors)
Decision thresholdStrictly more than 50% of votes cast
Max proof re-submission rounds3 (then auto-fail)
Voting eligibilityMust have donated to that specific milestone
Votes per address per round1

Reputation system

Each successfully completed milestone adds +1 to the vendor's on-chain reputation score. This score is permanent and publicly visible on Etherscan. It provides donors with a track record of the vendor before they contribute.

9. Troubleshooting

ProblemSolution
MetaMask shows wrong networkThe app auto-prompts to switch to Sepolia. If it fails, manually switch in MetaMask → Networks → Sepolia.
Contract not deployed to detected networkYou're on the wrong network, or deployed-addresses.json is outdated. Re-copy from root after deploy.
Transaction fails: "insufficient funds"You need Sepolia ETH for gas. Get some at sepoliafaucet.com.
USDC balance is 0Click Get 1000 Test USDC in the app. Each account needs to do this separately.
Vote buttons not showingYou must have donated to that specific milestone. The milestone must be in Voting Open state (proof has been submitted).
"Already voted" errorEach donor can only vote once per proof round. If a new proof round starts (needs-more-proof reset), you can vote again.
Proof Pending but vendor can't submitMake sure you're connected with the vendor or charity address that was used when the milestone was created.
IPFS file not loadingWait 1–2 minutes for propagation. Try https://gateway.pinata.cloud/ipfs/<CID> as an alternative gateway.
npx hardhat compile failsRun npm install first. Check Node.js version: node --version should be v18+.
Frontend not picking up new contractHard refresh: Cmd+Shift+R (Mac) or Ctrl+Shift+R (Windows). Also check that you copied the ABI files correctly.
